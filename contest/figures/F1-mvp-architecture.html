TRACE 아키텍처 (최종판)

부스 사진 폰 사진 (수령 촬영) 사진 무관 공용 인프라 박스 제목 = 실제 레포 이름

흐름 9단계

  1. 부스 태블릿에서 검사 기다리는 기기를 탭 (GET /api/v1/rentals, 스티커·QR 없음)
  2. CAM1·CAM2가 노트북 아래(BOT)·위(TOP)를 조명 L1·L2·L3로 찍어 사진 12장
  3. Jetson이 YOLO11-seg TensorRT로 흠집 폴리곤을 찾고 태블릿에 "문제 있음/없음"
  4. booth가 https://gakdo.site/api/v1/…로 부스 토큰·세트 생성·탐지 결과를 보냄 (강사님 nginx → web nginx → gateway → auth(토큰)·rental(목록)·capture(세트·탐지)). 사진은 사전 서명 URL …/trace-captures/…로 PUT해서 web nginx를 거쳐 MinIO에 저장
  5. 관리자가 web /admin에서 검사 결과(사진·폴리곤·판정)를 보고 흠집을 사람 검수(확정·기각), 수령 QR 발급, 진단 벤치마크 확인
  6. 고객이 폰으로 수령 QR(/capture?t=)을 열고 로그인·가입하면 auth_server가 렌탈을 계정에 연결. 폰으로 노트북을 찍어 사전 서명 URL로 MinIO에 올리면, 학교 서버 inspect-worker(ml, CPU)가 capture.uploaded를 받아 부스와 같은 v004 모델로 흠집을 찾고 면을 맞춘 뒤(윤곽 / SuperPoint+LightGlue) inspect.completed를 capture_server로 보냄. 진행률은 Redis
  7. 고객 노트북의 진단 에이전트(macOS)가 페어링 코드로 받은 토큰으로 진단 JSON(배터리·SSD·벤치마크·잠금·디스크 상태)을 gateway → diagnostics_server로 올림. diagnostics_server는 JSON Schema로 검증·저장하고 앞 진단과 비교해 점검 플래그를 붙인 뒤 diagnostics.recorded를 보냄
  8. report_server가 RabbitMQ에서 capture.uploaded·checkpoint.graded·diagnostics.recorded를 받아 타임라인과 해시 체인(Ed25519 서명)을 만들고, 봉인 사진을 MinIO에서 다시 해시해 시점을 봉인한 뒤 record.sealed를 보냄. 누구나 /verify에서 검증
  9. auth_server가 record.sealed를 받아 Gmail SMTP로 고객에게 봉인 영수증 메일

공개 /devices: 로그인 없이 보유 노트북을 흠집 수·배터리·벤치마크로 비교하고 상세에서 흠집 위치를 3D로 봄. 관리자가 확정한 부스 흠집과 진단 요약만 공개 (rental → capture·diagnostics catalog, IP당 분당 300회)

포트 목록

  • 443 gakdo.site (강사님 nginx, HTTPS)
  • 8315 web nginx, 학교 서버의 유일한 입구 (/api/ → gateway, /trace-captures/·/trace-derived/ → MinIO)
  • 8080 gateway·auth·rental·capture·diagnostics·report, Compose 안 (호스트에 안 열림) · inspect-worker는 포트 없음 (RabbitMQ 구독)
  • 5432 PostgreSQL · 6379 Redis (내부만)
  • 127.0.0.1:5672 RabbitMQ · 127.0.0.1:15672 관리 화면
  • 127.0.0.1:19000 MinIO API · 127.0.0.1:19001 콘솔 (9000은 다른 MinIO가 씀)
