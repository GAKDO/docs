11/9 MVP · https://gakdo.site

빌려주는 노트북의 상태를
사진 12장과 AI로 기록합니다

관리자가 웹에서 출고 검사를 열면, 부스가 노트북 아래·위를 조명 3개 × 카메라 2대로 찍고, 부스 안 AI가 흠집을 찾아 바로 "문제 있음/없음"을 띄웁니다. 서버는 등급 A~D를 저장하고, 관리자는 웹에서 결과를 봅니다.

12장2면 × 조명 3 × 카메라 2
15초버튼부터 판정까지 목표
A~DA = 문제 없음
서비스 5개+ 부스 앱 + 인프라 4개

검사 한 건은 이렇게 흘러갑니다

아래 번호는 전체 구조 그림의 동그라미 번호와 같습니다.

전체 구조

MVP에서 실제로 뜨는 것만 그렸습니다. 상자 하나가 프로그램(서비스) 하나입니다.

밖에서 들어오는 길은 하나

관리자 화면, 부스의 API 호출, 부스의 사진 올리기가 모두 gakdo.site 정문(443) → web nginx(8315)를 지납니다.

부스 화면은 Jetson이 띄웁니다

태블릿은 부스 와이파이 안에서 Jetson에만 붙고, 서버와 이야기하는 것은 Jetson의 booth 앱뿐입니다.

사진은 서버를 거치지 않습니다

capture-server가 준 10분짜리 주소로 사진이 MinIO(사진 창고)에 바로 들어갑니다.

점선은 학습 경로

모델을 만들 때만 쓰는 길입니다. 집 PC는 학습만 하고 서비스로 띄우지 않습니다.

서비스별로 보기

무슨 일을 하는지, 어디서 돌아가는지, 어느 기능에 쓰이는지. 작은 그림에서 진하게 보이는 곳이 그 서비스와 바로 연결된 곳입니다.

기능별 흐름 (F1 ~ F11)

일어나는 순서대로입니다. 단계마다 누가 → 어디로 보내는지와, 그때 쓰는 API를 적었습니다. API 이름을 누르면 API 문서로 갑니다.

검사 한 건 동안 바뀌는 상태

서버에 저장되는 값입니다. 화살표 위의 F 번호가 그 상태를 바꾸는 기능입니다.
